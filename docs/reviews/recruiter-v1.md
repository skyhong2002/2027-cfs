## V1-REC-01｜P1：人才交流篩選排除了基本攤位，卻留下攤位加大

狀態：已回報主代理修正 UI。

重現：切「人才交流」，搜尋「會場攤位」。實際只出現「會場攤位加大」一筆；改回「全部」才出現「會場攤位」及「會場攤位加大」。

原因：目標篩選在 `filterCatalog` 直接排除 `data-package=true`，即使基本攤位很符合人才交流目標。

影響：首次企業負責人會以為只能加大攤位，或者不知道基本攤位如何洽詢。

驗收：人才交流篩選可找到基本攤位與加大需求，並保持待確認狀態；不能因為草案分類是方案候選權益，就把最相關的交流方式藏起來。

## V1-REC-02｜P1：舊分類被推導成未確認的單買限制

狀態：已在模型修復，13 項單元測試通過，並以瀏覽器複測。

重現：未選任何方案，僅加入「會場攤位」，複製清單。修復前文字為「需搭配適用方案，非免費單品」，但 2027 的單買资格仍待確認。

原因：`isPackageOnly` 來自分類字串「打包專屬」，不能因此確定 2027 的商務限制。

修復：只有明確 `purchasable:false` 才產生需方案狀態；`purchasable:'pending'` 不受草案分類推定，回到 pending。修復後清單與品項顯示「2027 價格與適用權益待確認」。

相關 UI 建議：「方案內含」篩選與「方案權益」標籤應清楚標示是候選／待確認，避免使用者誤認為選定方案已附贈那些項目。

## V1-REC-03｜P2：列印內容缺乏可獨立識別及聯絡資訊

狀態：已回報主代理修正 UI。

重現：加入會場攤位，切換 print media 檢查列印輸出。品牌 header/footer 被隱藏，文件主標是「把想法，整理成下一步。」；沒有明確「SITCON 2027 合作討論清單」標題、聯絡 Email 或回訪網址。從主頁列印還留下「01 認識受眾／02 比較方案」導覽列。

影響：將 PDF 單獨傳給主管或採購時，來源、年份與聯絡方式不夠清楚，頁面導覽也成為無用資訊。

驗收：列印文件含 SITCON 2027 文件名稱、主辦聯絡信箱、可回訪網址及待確認說明；隱藏 `.section-index` 等畫面導覽；所選項目與網頁清單一致。
