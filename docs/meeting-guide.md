# 用第一版帶資訊流討論

預覽：<https://skyhong2002.github.io/2027-cfs/>。這次會議先驗證「企業窗口能不能做出下一步」，正式金額與權益另依待確認清單分派負責人。

## 30 分鐘示範與討論

1. **3 分鐘：交代已知與待確認。** 日期、地點已確認；方案 A–D 是討論代號，金額與權益還不能作商務承諾。先讓大家知道這版可以測選擇與洽談流程。
2. **7 分鐘：第一次合作的招募窗口。** 請一位沒看過新版的人找活動日期與地點，選人才交流方向，搜尋攤位、看詳情、加入清單，產生信件草稿。主持人先觀察，不代操作；記下他在哪個步驟找不到資訊或不知道怎麼選。
3. **5 分鐘：回訪品牌窗口。** 由年度合作進度入口進入，選方案 C、搜尋網頁 Logo，確認清單及草稿仍保留「現場與數位曝光」的需求方向。請操作者說出哪些是已確認、哪些只是洽談候選。
4. **5 分鐘：教育支持窗口。** 從開源築夢進入，不必先選方案即可表達支持意願，產生草稿並預覽列印。確認沒有把補助金額或支持人數誤認為已核定。
5. **7 分鐘：逐項決策。** 對每個卡點決定要移動資訊、補文案、修互動，還是向負責組別取得資料。每個獨立問題開一個 issue，指定一位負責人與驗收方式。
6. **3 分鐘：確認下一版。** 選出最影響理解或完成洽談的三件事優先處理；正式方案、截止日、受眾數字等由內容負責人提供可追溯來源。

## 主持人可以直接問

- 看完首屏，你會怎麼向主管介紹這次活動？還缺哪一項才願意往下看？
- 你為什麼選這個合作方向？如果現在無法選，需要補哪個資訊？
- 清單裡哪些內容你認為已經包含、需要另外付費，或仍需洽談？
- 收到這封草稿的行銷組，能不能看懂對方想解決什麼問題？
- 手機上能否完成同樣的路徑？下一步寄送是由誰完成？

## Issue 模板

```text
標題：[角色／步驟] 具體遇到的問題
來源：真人回饋／招募表單整理／模擬檢視（必須分清）
情境與目標：
重現步驟：
目前看到的結果：
對選擇或洽談的影響：
希望調整：
驗收：用哪個角色、裝置與操作確認改善
負責人／需要誰提供資料：
```

原始文件中的招募回饋是設計輸入；三份 agent persona 紀錄是額外的模擬測試，不能當成真實合作夥伴的意見。建議會後請實際企業窗口再走同一條流程。
